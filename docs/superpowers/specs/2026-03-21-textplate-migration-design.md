# Textplate Migration Design

## Summary

Migrate textplate from standalone repo (`~/code/textplate`) into the agentutils monorepo as `tools/textplate/`. Restructure the monolithic `textplate.py` into the standard agentutils tool pattern, add `tool-description` commands, create a Claude Code skill, and wire it into the installer.

## Background

Textplate is a markdown-based templating tool that composes documents from reusable snippets. It uses `text::` link syntax (`[label](text::source)`) to reference content from files and markdown sections, resolves all references, and outputs plain markdown. Primary use case: building documentation by combining modular content fragments.

**Current state:** Single `textplate.py` (~400 lines) with typer CLI, rich console output, comprehensive tests (unit + adversarial), and a demo directory.

## Module Split

### `core.py` — Template Processing Logic

Contains all pure logic with no CLI or UI concerns:

- **Exception:** `ResolveError` — raised when a reference cannot be resolved
- **Constants:** `LINK_PATTERN`, `HEADING_PATTERN`, `FENCE_PATTERN` regex patterns
- **`slugify(text)`** — GitHub-style heading slug generation
- **`_update_fence_state(in_fence, line)`** — Helper to track whether we're inside a fenced code block
- **`extract_section(content, section_slug, source_path, include_heading)`** — Find heading by slug, capture content until next same-level heading, skip headings in code fences
- **`resolve_reference(source, base_dir)`** — Resolve `text::` source to file content (whole files and `#section` fragments, with `!` suffix for including heading)
- **`process_template(template_content, base_dir)`** — Orchestrate: find all links, resolve all, validate, replace in reverse order
- **`make_header(source_name)`** — Generate the `<!-- Generated by textplate ... -->` comment
- **`compute_output_path(input_path)`** — Naming convention: `foo.textplate.md` → `foo.md`, `other.md` → `other.filled.md`
- **`press_file(file, to_stdout)`** — Execute press operation with header comment and newline normalization

### `watch.py` — Watch Loop

Contains the watch loop, progress bar, and related constants/helpers. Owns its own `Console()` instance.

- **Constants:** `INTERVAL_PATTERN`, `INTERVAL_MULTIPLIERS`, `BAR_CHAR`, `BAR_WIDTH`, `TICK_INTERVAL`
- **`parse_interval(interval_str)`** — Parse interval strings (`5s`, `2m`, `1h`, `1d`) into seconds
- **`format_interval(seconds)`** — Format seconds into human-readable strings
- **`_render_progress_bar(fraction)`** — Rich-based draining progress bar
- **`watch_file(file, interval_seconds, strict, verbose, no_progress)`** — Continuous re-pressing loop with error handling. Receives pre-parsed interval (float seconds), not raw string.

### `cli.py` — Typer Application

Thin wrappers calling into core and watch. The `watch` command handles argument validation (file existence, interval parsing/validation) before calling `watch.watch_file()` with parsed values.

- **`press`** command — Calls `core.press_file()`
- **`watch`** command — Validates args, parses interval string via `watch.parse_interval()`, calls `watch.watch_file()` with parsed seconds
- **`tool_description`** command — Prints `help.TOOL_DESCRIPTION`
- **`tool_description_short`** command — Prints `help.TOOL_DESCRIPTION_SHORT`
- **`main()`** — Wrapper that calls `app()`, used as entry point

Entry point: `textplate = "textplate.cli:main"`

### `help.py` — Agent-Oriented Descriptions

- **`TOOL_DESCRIPTION`** — Full description with usage examples, syntax reference, typical workflows. Written for agent consumption.
- **`TOOL_DESCRIPTION_SHORT`** — Concise version suitable for CLAUDE.md quick reference.
- **`COMMAND_HELP`** — Per-command help dict (press, watch).

## Skill Definition

`skills/textplate/SKILL.md` will describe:
- **When to use:** Working with `textplate.md` files, composing documentation from reusable snippets, resolving `text::` references
- **Key commands:** `press` (one-time resolution), `watch` (continuous)
- **Syntax:** `[label](text::path)` and `[label](text::path#section)` reference format
- **Typical workflow:** Create template with `text::` links, press to generate output

## Integration Points

1. **Installer:** Add `"textplate"` to `TOOLS` list in `tools/agentutils-install/src/agentutils_install/cli.py`
2. **Repo README:** Add textplate row to the tools table
3. **Skill install:** Already handled by `agentutils install-skills` which globs `skills/*/SKILL.md`

## Test Migration

Tests will be restructured to match the module split. All imports will change from `from textplate import ...` to `from textplate.core import ...` / `from textplate.watch import ...`.

- **`test_core.py`** — Tests from original `test_textplate.py` that exercise core logic (regex matching, slugify, section extraction, reference resolution, template processing, path handling)
- **`test_cli.py`** — Tests for CLI commands including the new meta-commands (tool-description, tool-description-short)
- **`test_adversarial.py`** — Carried over with updated imports (duplicate headings, inline markdown, fenced code, circular references, Windows line endings, binary files, path traversal)
- **`fixtures/`** — All test fixture files carried over, including loose `.md`/`.txt` files from the original `tests/` directory

All tests must pass with `uv run --directory tools/textplate pytest`.

## What's NOT Migrated

- Original repo's `README.textplate.md` (meta-template for generating its own README) — replaced by a standard README.md
- Original repo's `docs/reference.md` — content folded into TOOL_DESCRIPTION and README
- Git history — this is a fresh addition to the monorepo, not a subtree merge
